## 1. What this site is

One Next.js application serving four purposes at once:

1. **Portfolio** — résumé, projects, certifications
2. **Accounts** — anyone can sign up, verify email, keep a public profile
3. **Community** — a Reddit-style feed where members post
4. **Games** — browser games hosted on the site

It is deliberately *one app*, not four. A member signs in once and that identity
carries everywhere. Do not split it into separate products.

### Long-term direction

A private file and photo area is planned (Drive/Photos-like), backed by an 8 TB
USB HDD on the Proxmox host. The decision on record is **do not build it** —
run Immich and Nextcloud on subdomains and make miguisanson.dev the portal in
front of them. See §9.

## 3. Stack and hard constraints

- **Next.js 16 App Router**, React 19, TypeScript
- **Better Auth 1.7.2** — email + username, verification required
- **SQLite** for local development, **PostgreSQL** in production
- **Hand-written CSS. No Tailwind.** This is a deliberate, standing decision.
- **Fonts self-hosted via `next/font`** — never link a font CDN

### Things that will bite you

- **Better Auth has no OIDC *provider*.** It ships `generic-oauth`, which makes
  this site an OAuth *client*. Single sign-on into other services needs a real
  identity provider (Authentik, Keycloak, Pocket ID). Verified 2026-08-27.
- **The `account` table has a NOT NULL `issuer` column.** Credential accounts use
  `local:credential`. Any hand-written insert that omits it fails.
- **`AGENTS.md` is regenerated by `next dev`.** Do not treat edits to it as
  durable — this file is the durable one.

## 4. Design system — the formatting rules

All styling lives in **`src/app/globals.css`**. Structure, in order:

1. **Token block** (top of file) — the single source of truth
2. Base reset and element defaults
3. Legacy component sections
4. **Revamp layer** (bottom) — restyles existing classes, wins the cascade

### Non-negotiable rules

- **Never hard-code a colour in a component.** Every colour resolves through a
  token defined for *both* themes. A colour defined only inside a `[data-theme]`
  block renders wrong in the other theme.
- **Watch specificity.** The revamp layer sits at the bottom, so equal
  specificity wins. But older rules like `.profile .profile_inner > span` and
  `.sidebar-nav ul` outrank single-class selectors. Match their specificity —
  **never reach for `!important`.**
- **Hover changes colour and elevation only, never `transform`.** Transforms
  shift layout under the cursor.
- **Active navigation** uses an accent rail plus a tinted background, never a
  font-weight change (weight changes reflow the label).
- **No emoji as icons.** SVG only, 24px viewBox, in `components/layout/NavIcons`.
- **Touch targets ≥ 44px** on coarse pointers.
- Respect `prefers-reduced-motion`.

### Palette intent

Blue-biased neutrals — never flat grey, so they read as chosen. One emerald
action colour for primary buttons, links, active nav and focus rings. Status
colours (success / warning / danger / info) are **separate** from the action
colour and must not be repurposed as accents.

### Type roles

| Role | Face | Used for |
| --- | --- | --- |
| Display | **Archivo** | Headings, card titles, brand |
| Body | **Geist** | Running text, controls, forms |
| Mono | **Geist Mono** | Timestamps, counts, handles, chips, code |

Metadata reads as *data*, not prose — that is why it is mono and
`tabular-nums`.

### Naming

- `ui-*` — reusable primitives (`ui-button`, `ui-card`, `ui-badge`)
- `page-header`, `doc-*`, `release-*` — page-level structures
- Component-scoped names elsewhere (`community-card`, `game-card-v2`)

**Beware collisions.** `.game-list` / `.game-card` belong to the *profile
favourites list*; the games index uses `.card-grid` / `.game-card-v2`. This has
already caused one bug.

## 5. Information architecture

| Route | Who | Purpose |
| --- | --- | --- |
| `/` | Public | Greeting + section cards |
| `/resume` | Public | Portfolio. Mirrors the current one-page CV. |
| `/blog`, `/blog/[slug]` | Public | Long-form written posts, authored by the owner |
| `/games`, `/games/[slug]` | Public | Game index; launching needs a verified account |
| `/community` | Public read | **The post feed.** Members compose here. |
| `/members` | Public | Member directory and search |
| `/u/[username]` | Public* | Profile. **Read-only — no composer.** |
| `/account/**` | Signed in | Settings, profile, security |
| `/admin` | Admin | Dashboard, audit log, blog authoring |
| `/changelog`, `/docs` | **Admin only** | Project reference (see §7) |

### Deliberate separations

- **Blog ≠ Community.** Blog is long-form, owner-authored. Community is short
  member posts. They are different content types and must stay separate.
- **Members ≠ Community.** Members is *people*. Community is *posts*.
- **Profiles do not compose.** Writing happens on `/community`, never on a
  profile page. A profile displays a member; it is not an editor.

## 6. Content conventions

- **Résumé content lives in `src/data/profile.ts` and `src/data/projects.ts`**,
  and must track the current one-page CV. Games are **not** portfolio projects —
  Here to Slay belongs on `/games`, not the résumé.
- **Blog posts** are markdown in `content/blog/`, front-matter at the top.
  Admin-authored posts are stored in the database. The index merges both.
- **User posts are escaped before formatting** (`markdownToHtml` in
  `src/lib/content.ts`). That ordering is what makes the feed XSS-safe.
  **Never reverse it. Never swap in a renderer that emits raw HTML.**

## 7. Security posture

Established and verified 2026-08-27:

- Every SQL query is parameterized. No string-built SQL, ever.
- Every server action checks the session; mutations verify ownership.
- Security headers site-wide; CSP currently **Report-Only**, flag in
  `next.config.ts`.
- The DD Project game route gets its own looser CSP — the GameMaker runtime needs
  `eval` and WebAssembly. Do not widen the site-wide policy to accommodate it.
- `/account` and `/admin` send `no-store`.

### Two standing rules

1. **Do not publish exploitable specifics.** `/docs` must never enumerate which
   security work is outstanding — that is a checklist for an attacker.
   Outstanding items belong in `ROADMAP.md`.
2. **`/changelog` and `/docs` are admin-gated** via `projectPagesArePublic` in
   `src/lib/site-config.ts`, and return **404** (not 401) so their existence is
   not disclosed. Gate in the page itself; hiding nav links is cosmetic.

## 8. Working conventions

### Changelog — required

Every change gets a dated entry. **Absolute dates only** (`## YYYY-MM-DD`), never
relative. Day one of tracked development is **2026-08-27**.

Update **both**:
- `CHANGELOG.md` (repository)
- `src/data/changelog.ts` (renders `/changelog`)

Then move the item to Done in `ROADMAP.md`. Do not add a fourth tracker.

### Before reporting work complete

```bash
npx tsc --noEmit     # must be clean
npm run build        # must pass
npm audit --omit=dev # must report 0 vulnerabilities
```

### Do not

- Deploy. Miguel deploys himself; build and verify locally only.
- Commit unless asked.
- Introduce Tailwind or a CSS framework.
- Hardcode credentials — the repository is public.
- Use `!important` to win a specificity fight.

## 9. Decisions on record

| Decision | Rationale |
| --- | --- |
| **No Tailwind** | Hand-written CSS with tokens. Standing decision, do not revisit. |
| **One app, not four** | Single identity across portfolio, community and games. |
| **Adopt Immich/Nextcloud, don't build storage** | A Drive/Photos clone is a multi-year product, and the mobile auto-backup app cannot realistically be built solo. |
| **Originals go straight to HDD; SSD is pure cache** | Rejected the "fill 32 GB then offload" idea — it makes the authoritative copy mobile, so a mover bug loses originals. The SSD must never hold the only copy of anything. |
| **Second drive before features** | A single USB HDD is capacity, not redundancy. USB bridges reset under load; that is the most common home-server data-loss path. |
| **Services keep their own subdomains** | Proxying Immich behind a custom UI breaks its mobile app, which is the reason to run it. |
| **`/changelog` + `/docs` admin-gated** | Owner's call. Flag exists to make them public again if the portfolio value wins. |
| **Games excluded from the résumé** | Here to Slay is a game, not a case study; it was duplicated on both pages. |
